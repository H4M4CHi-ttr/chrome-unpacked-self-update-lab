# 更新処理と権限の保持を分離する実験

拡張機能全体の再読み込みで書き込み許可が `prompt` に戻る現象に対し、次の2方式を検証するための独立したプローブです。既存の `extension` にある GitHub 自己更新実験は変更していません。

- 固定の画面・サービスワーカーを動かしたまま、書き換えた `active.js` を別のモジュール URL で読み直す。
- 別の HTTPS 更新ページでフォルダへのアクセスを維持し、更新対象の拡張機能だけを再読み込みする。

権限の保持を切り分けるため、更新内容は同梱の固定ソースを使います。GitHub Releases の定期確認、署名検証、ZIP 展開をこのプローブに再実装していません。それらの実機結果はリポジトリ直下の RESULTS.md を参照してください。

## 起動

1. Chrome Stable のプロファイル「AI Agent」で開発者モードを ON にし、このディレクトリの `extension` を読み込みます。
2. `chrome-extension://<拡張機能ID>/index.html` を独立タブで開きます。
3. 同じ `extension` フォルダを登録して、読み書きを許可します。
4. 「2回の自動更新を開始」を押します。以後の書き換えはユーザー操作の有効期間が過ぎた6秒後に行い、もう6秒待って次の版へ更新します。

ホットモジュール方式では、0.2.0 → 0.2.1 → 0.2.2 を試します。実ファイルを置き換え、キャッシュキーを変えた自分自身の URL から新しい JavaScript モジュールをインポートして関数を実行します。`eval()` は使いません。固定のサービスワーカーは更新しないため、その起動IDが変わらないことも確認します。

## 別 HTTPS ページ

対象画面の「HTTPS更新ページで開く」で、GitHub Pages 上の独立した更新ページを開きます。対象の拡張機能IDは自動で渡されます。

HTTPSページには、拡張機能内とは別に一度フォルダを登録する必要があります。権限の主体が別のオリジンになるため、ハンドルを引き渡して省略することはしていません。同じ対象フォルダを選択してください。

この方式は0.2.3と0.2.4を順に書き込みます。各回で拡張機能自身の URL から内容を読み返し、その後、許可した HTTPS ページからのメッセージで対象の拡張機能だけを再読み込みします。新しいサービスワーカーの版と起動ID、更新ページの実行ID、更新前後の権限を記録します。

Chrome再起動後も再許可を省くには、保存したハンドルを復元し、「保存フォルダを再許可」から表示される Chrome の「サイトアクセス時は常に許可」を選びます。検証では、この選択後にChromeを完全終了して再起動し、起動直後の `granted` と、再許可なしでの2回の更新を確認しました。フォルダを選び直す操作は不要でした。

更新処理が動く間は、このHTTPS更新ページを開いておく構成です。タブを閉じたままOS上で更新処理が動く仕組みではありません。

通信は固定のプロトコルとアクションに限定しています。対象は GitHub Pages の正確な HTTPS ページだけを許可し、指定された版の固定ソースと現在のファイルが一致する場合だけ再読み込みに応じます。

## 安全範囲

書き込み対象は、登録したフォルダの既存 `active.js` だけです。固定ファイルを照合し、元のコードを IndexedDB に退避してから置換します。書き込み・読み返し・新コードの確認で失敗した場合は元に戻します。復元にも失敗した場合は画面のバックアップ復元ボタンを使えます。

2方式を同時に実行しないでください。別オリジン間の同時更新や、外部エディタとの競合を扱う製品実装ではありません。

このプローブは単一の対象で検証する構成です。対象を別のパスから読み込み直した場合や別コピーを使う場合は、HTTPSページでも対象フォルダを選び直してください。

## 検査

リポジトリのルートで送信元とメッセージの制限を検査できます。

```powershell
node --test tests/isolation.test.mjs
```

実機の更新ログを `evidence/hot-module.json` と `evidence/external-https.json` に保存した後は、次のコマンドで2回ずつの更新、実行、権限、起動IDを照合できます。

```powershell
node tools/verify-isolation-evidence.mjs
```

[実測結果と証跡](RESULTS.md) に、2方式での更新とChrome再起動後の結果を記録しています。PWA のインストールや、OS 起動時の自動実行はこのプローブには含めていません。
